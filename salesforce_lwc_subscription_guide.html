購読（subscribe）と
ライフサイクルフック

Bike A・Bike Bを選択する例で、メッセージ送信・受信・購読解除の仕組みを、図・動作デモ・コードで順番に学びます。

この教材のゴール： connectedCallback() で購読し、publish() でIDを送り、disconnectedCallback() で解除する流れを説明できるようになること。

01. 全体像

送信側は bikePicker、受信側は bikeInfo です。両者は BikeSelected というメッセージチャネルを共有します。

bikePicker選択ボタン / publish()
→
BikeSelectedメッセージチャネル
→
bikeInfosubscribe() / 表示
今回送るのは { bikeId: 'A' } のようなIDだけ。バイク名や価格は、受信側にあるデータから取得します。

02. まず用語を整理

用語役割今回の例
subscribe()メッセージを受け取る登録bikeInfoが待ち受ける
publish()メッセージを送信するBike AのIDを送る
unsubscribe()購読を解除する終了時に受信をやめる
connectedCallback()DOMに追加されたときに呼ばれる購読開始のタイミング
disconnectedCallback()DOMから削除されたときに呼ばれる購読解除のタイミング
message送られてきたデータ{ bikeId: 'A' }

04. どの順番で実行される？

順番実行される処理何が起こるか
1handleSelect()選択したバイクIDを保存して子を表示
2connectedCallback()bikeInfoがDOMに追加される
3subscribe()チャネルの購読を開始
4publish()選択したIDを送信
5handleMessage()IDを受け取り、詳細情報を表示
6disconnectedCallback()子が削除されたときに実行
7unsubscribe()購読を解除

05. ソースコード

タブでファイルを切り替えられます。コードはコピーできます。

実装時の注意： 学習用コードの @wire(MessageContext) は初期化タイミングに注意が必要です。実際のSalesforceではコンテキストの準備を確認してから購読してください。ready 通知は購読登録完了後に送る必要があります。

06. 重要コードを一行ずつ読む

① 購読を開始する

this.subscription = subscribe(
    this.messageContext,
    BIKE_CHANNEL,
    (message) => this.handleMessage(message)
);
コード意味
this.subscription =後で解除できるよう購読情報を保存する
this.messageContextLMSが使用するコンテキスト
BIKE_CHANNEL購読するメッセージチャネル
(message) => ...メッセージが届いたときに呼ばれる関数

② IDを送信する

publish(this.messageContext, BIKE_CHANNEL, {
    bikeId: this.selectedBikeId
});

publish() の第3引数が送信するデータです。Bike Aなら { bikeId: 'A' } になります。

③ IDから情報を取り出す

handleMessage(message) {
    this.selectedBike = this.bikes[message.bikeId];
}

受信した message.bikeId が 'A' なら、this.bikes['A'] を参照します。名前や価格そのものを送っているわけではありません。

④ 購読を解除する

disconnectedCallback() {
    if (this.subscription) {
        unsubscribe(this.subscription);
        this.subscription = null;
    }
}

if (this.subscription) は購読情報が存在するかを確認しています。解除後は null に戻します。
